# Mobile developer handoff: Admin-managed app configuration

The mobile app reads settings published in Sancharie Admin through the public customer API. It must not sign in to `/api/admin` or embed an Admin JWT, password, or secret.

## Base URL

Set `API_BASE_URL` to the deployed Sancharie backend origin, for example `https://<deployed-api-host>`. Do not ship `localhost` in the app. The currently configured production host `https://api.sancharie.com` returned 404 for `/api/config` on 7 Oct 2026, so the updated backend must be deployed and the live URL confirmed before release.

## Admin-managed configuration

### Fetch current values

```http
GET {API_BASE_URL}/api/config
Accept: application/json
```

No API key or customer login is required. Fetch on app launch and resume; the response is cached for 60 seconds.

```json
{
  "success": true,
  "data": {
    "appIconUrl": "/api/app-icon?v=1791388800000",
    "settings": {
      "maintenanceMode": false,
      "bookingsEnabled": true,
      "registrationEnabled": true,
      "couponsEnabled": true,
      "discountsEnabled": true,
      "festivalThemeEnabled": true,
      "contactEmail": "support@example.com",
      "contactPhone": "+911234567890",
      "supportInformation": "Contact support for help.",
      "announcement": ""
    },
    "theme": {
      "name": "Diwali",
      "festival": "Diwali",
      "primaryColor": "#1746a2",
      "secondaryColor": "#f3a712",
      "backgroundColor": "#ffffff",
      "bannerImage": "https://example.com/banner.png",
      "logoImage": "https://example.com/logo.png",
      "icon": "",
      "promotionalText": "Seasonal offers are live",
      "ctaText": "Explore"
    },
    "banners": [],
    "discounts": [],
    "coupons": [],
    "offers": []
  }
}
```

`appIconUrl` is `null` until uploaded. Resolve it against the API origin, since it is a relative path:

```js
const iconUrl = data.appIconUrl
  ? new URL(data.appIconUrl, API_BASE_URL).toString()
  : null;
```

The icon image itself is available at `GET {API_BASE_URL}/api/app-icon` (the version query string from `appIconUrl` is recommended for cache invalidation). Use it as the in-app brand image. Updating an installed native launcher icon requires platform-specific native support and cannot be done by loading this URL alone.

`theme` is `null` when no scheduled theme is active or festival themes are disabled. Theme fields: `name`, `festival`, `primaryColor`, `secondaryColor`, `backgroundColor`, `bannerImage`, `logoImage`, `icon`, `promotionalText`, `ctaText`.

`banners` contains currently active customer-facing banners. Each item can contain `title`, `description`, `image`, `ctaText`, `ctaUrl`, `kind`, and `priority`.

`discounts` contains enabled discounts in their active date window when `settings.discountsEnabled` is true. A discount can include `name`, `description`, `code`, `bannerImage`, `percentage`, `maximumDiscount`, `minimumBooking`, `applicableRoutes`, `startDate`, and `endDate`.

`coupons` contains enabled coupons in their active date window when `settings.couponsEnabled` is true. A coupon can include `code`, `name`, `type` (`percentage` or `fixed`), `value`, `maximumDiscount`, `minimumBooking`, `applicableRoutes`, and `endDate`.

`offers` contains active Admin offers, with fields such as `name`, `description`, `type`, `discountType`, `discountValue`, `maximumDiscount`, `minimumBooking`, `applicableRoutes`, `bannerImage`, `priority`, `startDate`, and `endDate`.

### Important current limits

- The config endpoint supplies customer display/configuration data. There is currently no public coupon validation/redemption endpoint; do not calculate or trust a final booking price on the device based only on these display values.
- Referral attribution is supported during account creation, and the signed-in referral summary is available below. Referral reward values and automatic reward qualification are not configured yet.
- The push registration endpoints currently accept browser/Web Push subscriptions. Native iOS/Android push requires separate native push integration.

## Push notifications

These endpoints support the existing browser Web Push implementation:

```http
GET    {API_BASE_URL}/user/push/public-key
POST   {API_BASE_URL}/user/push/subscriptions
DELETE {API_BASE_URL}/user/push/subscriptions
```

The public key endpoint needs no login. Subscription create/delete requests require the normal customer JWT:

```http
Authorization: Bearer {CUSTOMER_JWT}
Content-Type: application/json
```

Create body:

```json
{
  "subscription": {
    "endpoint": "https://push-service.example/subscription",
    "expirationTime": null,
    "keys": { "p256dh": "...", "auth": "..." }
  }
}
```

Delete body:

```json
{ "endpoint": "https://push-service.example/subscription" }
```

Booking/refund notifications are generated by the backend. Promotional campaigns are sent from Admin to opted-in subscriptions.

## Referral APIs

Pass a referral code as `referralCode` to `POST {API_BASE_URL}/user/login-complete` after OTP verification when creating a new account. The code format is `SAN` plus 10 hexadecimal characters. A signed-in customer can retrieve their own code and counts:

```http
GET {API_BASE_URL}/user/referrals/me
Authorization: Bearer {CUSTOMER_JWT}
```

## Other mobile endpoints

Customer OTP, profile, booking, payment, bus, flight, and hotel endpoints are existing app APIs rather than Admin-configuration APIs. The mobile developer should use the same customer endpoints and customer JWT flow as the website where those features are needed; never substitute an Admin token.
